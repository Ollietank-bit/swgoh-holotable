# swgoh.gg CAPTURE tool (tools/swgoh-capture.js + parse-capture.js)

One injected script reads everything the refresh needs from swgoh.gg (rosters, GAC brackets, schedule, 5 tier boards, datacrons, raid page), extracts it in-page and saves ONE gzip to the user's Downloads. It returns only a <=300-char summary (no URLs), so the javascript_tool 1 KB cap never matters. The file is a superset of the bookmarklet pull file, so "☁ Sync → Import pull file…" in the app accepts it too.

**Chrome procedure (orchestrator):**
1. `tabs_context_mcp` → pick a tab (or `tabs_create_mcp`), `navigate` it to `https://swgoh.gg/schedule/`. Let the Cloudflare "Just a moment…" check finish (`get_page_text` shows the schedule / "TIMES IN AUSTRALIAN EASTERN TIME"). The page should show Australian Eastern time (parse-capture refuses any other zone).
2. `javascript_tool` with the whole text of `tools/swgoh-capture.js` as `text`. Result = summary, e.g. `holotable-capture-2026-11-01-0251 json.gz 2900KB saved | ollie ok 8.44M, tiny ok 8.10M | schedule 19, 5v5 30, 5v5def 9, 3v3 12, 3v3def 5, fleet 21, dcron 7, raid 8 | gac ollie S84w3 7/7 opp, tiny … | no issues | 41s`. A `*` after a count = rows came from the live tab / an iframe render instead of fetched HTML. If the tool returns early (empty or timeout), the capture keeps running in the tab: call `javascript_tool` again with `window.__holotableCapture.summary` after 30–60 s (`window.__holotableCapture.status` is `running` until done; `.save()` re-triggers the download; `.out.pages.schedule.rows` is inspectable).
3. Read the file: `device_list_dir ~/Downloads` (grant the folder once with `device_request_folder_access` if needed) → newest `holotable-capture-*.json.gz` (Chrome may add ` (1)`) → `device_stage_files` → `node tools/parse-capture.js /mnt/user-data/uploads/Downloads/<file> refresh.json`. Exit 2 = timezone refused; 1 = bad file.
4. `refresh.json` holds: `rosters.<acct>.compact` (ref31/ollie-roster-31oct.txt format) + GLs/GP/last_updated/mods, `gac` bracket summary, `schedule.events` (startUtc/endUtc, `date` = first day, `ends` = last live day: a close at/before 06:00 local counts the previous day), `boards.tierGac|tierGacDef|tier3v3|tier3v3Def|tierFleet` -> **`squads[]`** (ONLY real squad rows: rank from the page's `#N`, tier, trendText/trend/isNew, tierChange, leader, units[], elo, win / hold %, battles + battlesN, builds, datacronDependent, banners, flags) + `squadCoverage` (ranks strictly increasing, rankGaps); `rows` is DEPRECATED raw extractor output incl. datacron-tooltip noise, `datacrons.sets` (expiresDate), `raid`, and `coverage` (missing / textOnly / suspicious — read it first).

**If a page shows `0` (text only) in the summary** — its HTML is client-rendered and the fetched copy was an empty shell: `navigate` the tab to that page, run `javascript_tool` with `window.__holotableCaptureConfig={mode:"live"};` prepended to the script text (extracts the CURRENT tab's live DOM into a store in session/localStorage; summary says what the store holds). Repeat per page, then run once more with `window.__holotableCaptureConfig={mode:"flush"};` on any swgoh.gg tab: APIs are re-fetched, stored pages replace fetched ones, the file downloads, the store is cleared. Other options (same object): `apis:false`, `gacPlayers:false` (skip opponent rosters, much smaller file), `iframe:false`, `download:false`, `origin` (selftest only).

**Offline proof:** `NODE_PATH=/home/claude/.npm-global/lib/node_modules node tools/capture-selftest.js` (52 checks (47 + 5 real-shaped squad checks on fixtures/real-tier-rows-1nov.json, derived from the real 1 Nov capture): round trip on tools/fixtures, DST/rollover, bad-tz refusal, Cloudflare stop, zero-rows fallback, live+flush). Fixtures are hand-written stand-ins for swgoh.gg's real markup (the defence boards are marked SYNTHETIC); the real DOM may differ — the extractors are text-pattern based (times, "Ends …", "%", "Expires …", img alt) rather than class based for that reason, and every row keeps its raw `leaves` so nothing is lost.
